Files to databases

Limitations of the file-based approach

Separation & isolation

Data is split across files; combining it needs custom code for every question.

Duplication

The same facts are stored many times: wasted space and inconsistent copies.

Program–data dependence

The file layout is coded into each program. Add a field and every program must change.

Incompatible formats

COBOL, C, Excel, CSV… files written by one program cannot be read by another.

No integrity rules

Nothing stops a negative salary or an order for a customer who does not exist.

No concurrency or recovery

Two users updating the same file at once, or a crash mid-write, can corrupt data.
