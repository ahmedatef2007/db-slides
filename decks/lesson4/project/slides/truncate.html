Fixed: the original said TRUNCATE 'can't be rolled back because it's a DDL statement'. That is true in Oracle and MySQL but not in SQL Server or PostgreSQL, where TRUNCATE inside an explicit transaction can be rolled back. Also TRUNCATE usually fails on a table referenced by a foreign key, and resets identity columns in SQL Server.
